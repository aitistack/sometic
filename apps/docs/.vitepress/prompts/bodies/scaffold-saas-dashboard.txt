================================================================================
PRODUCT TO BUILD
================================================================================
Name: Northline Dashboard (B2B SaaS home)
Users: signed-in operators at a company using modules (Overview, Customers, Settings).
Outcome: One App Shell runtime with auth, HTTP, query tables, notifications, command palette, tabs, and feature-flagged modules.

================================================================================
NON-NEGOTIABLE RULES
================================================================================
- Auth session + HTTP refresh + Query cache composed via createAppShell / createSometicApp
- Server lists live in @sometic/query (+ data-table). UI chrome (sidebar collapsed) lives in @sometic/store
- createFeatureFlagController gates modules; server still enforces entitlements
- createPermissionController / can() is UX-only
- Structure Tabs + Command palette: A/B use /structure adapters; C use @sometic/dom (NO Tabs/Command-palette CEs invented)
- Data table: A/B use /data adapters; C use engine + DOM (NO invented data-table CE)
- Unstyled packages; consumer CSS for dense SaaS layout
- No playgrounds, Invoice Desk, telemetry, invented packages, Google Fonts in packages
- No browser globals at import time
- Pin exact @sometic/* versions (never "latest"); ship unit + e2e tests
- Page-lifetime System singleton; do NOT dispose shell/auth/forms on React Strict Mode / Vue remount cleanup
- Pass naked createHttp into createAppShell; use shell.http; forms via connected fields; guards via isAuthenticatedStatus (A: useRequireAuth)

================================================================================
REQUIRED PACKAGES
================================================================================
@sometic/app-shell, @sometic/auth (+ adapter), @sometic/http, @sometic/query,
@sometic/data-table, @sometic/notifications, @sometic/feature-flags,
@sometic/store, @sometic/theme, @sometic/head, @sometic/forms (settings forms),
framework /structure + /data + /overlay (toast) + /auth hooks

================================================================================
SCREENS
================================================================================
1. Sign-in (minimal; can deep-link from Auth scaffold patterns)
2. App shell with sidebar: Overview, Customers, Settings, Billing (flagged)
3. Customers: data-table with sort/filter stubs, row actions permission-gated
4. Notifications center entry + toast on successful mutation
5. Command palette: Navigate to Customers, Create customer (if permitted), Toggle theme
6. Settings: profile form via @sometic/forms

================================================================================
WIRING RECIPE
================================================================================
1. createAuth + http interceptor + query client
2. createFeatureFlagController({ definitions, remote/overrides as needed })
3. createPermissionController from auth capabilities returned by /me
4. createAppShell({ auth, http, query, head, theme, stores, forms })
5. Register commands that call router.navigate / open dialogs
6. On session epoch change: drop privileged query data / remount module outlets
7. Do not dispose page-lifetime System on Strict Mode effect cleanup (useRef singleton)

================================================================================
ACCEPTANCE CRITERIA
================================================================================
[ ] Authenticated shell renders only after hydrate
[ ] Customers table data comes from query keys, not store
[ ] Mutating a customer invalidates/refetches the list
[ ] Billing route unreachable in UI when flag off
[ ] Permission-denied actions hidden OR disabled AND API rejects if forced
[ ] Command palette navigates without full reload
[ ] Toast confirms save; notification inbox shows assignment-style events
[ ] dispose cleans up; remounting root does not duplicate listeners
