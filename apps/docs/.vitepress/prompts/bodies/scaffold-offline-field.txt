================================================================================
PRODUCT TO BUILD
================================================================================
Name: Fieldkit Capture
Users: field technicians capturing forms without reliable connectivity, then syncing.
Outcome: Drafted forms + offline mutation queue + conflict resolution on reconnect + query as server truth after sync + auth hydrate when online.

================================================================================
NON-NEGOTIABLE RULES
================================================================================
- @sometic/offline-queue retries TRANSPORT; @sometic/conflict owns merge policy; @sometic/query holds server truth after sync
- @sometic/drafts for in-progress forms (omit secrets)
- @sometic/store persistence for client field state you intentionally keep
- Only enqueue mutations your API can accept idempotently later
- Reconnect order: hydrate auth → flush queue → conflict strategies → invalidate query
- createAppShell; dispose contracts for listeners/in-flight HTTP; document queue durability across reloads
- Large touch targets; high contrast; prefer native inputs
- No Invoice Desk, playgrounds, telemetry; no import-time navigator/window

================================================================================
REQUIRED PACKAGES
================================================================================
@sometic/offline-queue, @sometic/drafts, @sometic/conflict, @sometic/forms,
@sometic/validation, @sometic/store, @sometic/http, @sometic/auth, @sometic/query,
@sometic/app-shell, framework field adapters
Optional: Workbox / vite-plugin-pwa (explicitly yours)

SCREENS
================================================================================
1. Sign-in (online)
2. Inspection list (query when online; last-known cache messaging when offline)
3. Capture form with draft autosave
4. Offline banner + pending queue count
5. Conflict UI comparing server vs local fields
6. Sync success → refreshed query list

================================================================================
WIRING RECIPE
================================================================================
1. App Shell with persisted store + offline queue storage
2. Form bind + drafts
3. On submit: if offline → enqueue; if online → http then invalidate
4. online event → auth.ensure/hydrate → flush queue → conflicts → query.invalidate
5. dispose: abort in-flight; do not assume queue memory-only unless documented

================================================================================
ACCEPTANCE CRITERIA
================================================================================
[ ] Fill form offline, reload, draft still present
[ ] Submit offline increases queue; reconnect flushes

[ ] After sync, query list matches server
