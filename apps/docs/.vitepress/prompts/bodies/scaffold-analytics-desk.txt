================================================================================
PRODUCT TO BUILD
================================================================================
Name: Signal Reports
Users: analysts filtering datasets, viewing tables, glancing at charts, importing/exporting CSV.
Outcome: query-builder filters → query-cached results → data-table + optional chart; uploads for import jobs.

================================================================================
NON-NEGOTIABLE RULES
================================================================================
- Filters: @sometic/query-builder → serialize to YOUR API filter contract
- Results: @sometic/query keys include serialized filters
- Presentation: data-table via /data adapters
- Files: field/file input collects; @sometic/upload transports (progress/abort)
- Charts: third-party only
- Auth + App Shell for gated desk; page-lifetime System (no Strict Mode dispose of create-once refs); pin @sometic versions; unit + e2e tests
- Prefer filter state in URL for shareable reports
- No playgrounds, Invoice Desk, telemetry, invented Sometic viz packages

================================================================================
REQUIRED PACKAGES
================================================================================
@sometic/app-shell, @sometic/auth, @sometic/http, @sometic/query,
@sometic/query-builder, @sometic/data-table, @sometic/upload, @sometic/theme,
framework /data adapters, plus CHART_LIB of your choice

================================================================================
REPO LAYOUT
================================================================================
src/

  reports/
    filter-panel.tsx          // query-builder UI

    results-chart.tsx         // wraps chosen chart lib
    serialize-filters.ts
  import/

  hooks/use-report-query.ts
  mocks/api.ts
  styles/reports.css
README.md                     // MUST name chart library + honesty note

================================================================================
DOMAIN STUBS
================================================================================
FilterAst: whatever query-builder emits (map to API)
ReportRow: { id, dimension, metric, date }
ImportJob: { id, status: "queued"|"running"|"done"|"error", filename }

API:
- GET /reports/query?filter=...
- POST /reports/import (multipart)
- GET /reports/import/:id

================================================================================
SCREENS
================================================================================
1. Sign-in
2. Report desk: filter panel | results table | chart
3. Import drawer/modal with upload progress
4. Empty/error/loading states for query

================================================================================
WIRING RECIPE
================================================================================
1. App Shell auth/http/query/theme
2. Build filters with query-builder; sync to URL search params
3. useQuery(["report", serialized]) → rows
4. DataTable binds rows; chart maps rows → series
5. Upload import; poll job status via query
6. High-contrast tokens via theme helpers for dense UI

================================================================================
IMPLEMENTATION STEPS
================================================================================
1. Vite app + mock report API
2. System bootstrap
3. Filter panel + URL sync + serialize helper

5. Chart integration (explicit dependency)
6. CSV import upload + status
7. README with chart choice, filter mapping notes, performance caveats for huge exports

================================================================================
ACCEPTANCE CRITERIA
================================================================================
[ ] Changing filters refetches with new query key
[ ] Shared URL reproduces the same filter set
[ ] Table and chart reflect the same result set
[ ] Upload shows progress and completes job
[ ] README states chart library and “no @sometic/charts”
[ ] No multi-hundred-MB CSV parsed entirely on main thread without warning
