================================================================================
PRODUCT TO BUILD
================================================================================
Name: Auth App (end-to-end session product)
Audience: End users who sign up / sign in, then use a small protected product area.
Outcome: A runnable Wave A app where auth, HTTP refresh, query cache, forms, head, and theme are composed correctly through App Shell, with clean dispose, unit tests, and Playwright (or equivalent) e2e coverage — on the path the user selected.

Ideal means: boots without inventing APIs; sign-up/sign-in navigate; titles/theme apply; mocks match auth-local; guards treat refreshing as authenticated; tests pass.

DOMAIN + MOCK CONTRACT
================================================================================

ProfileListItem: { id, title, updatedAt }

Mock MUST implement auth-local defaults:
- POST /auth/sign-in
- POST /auth/register
- POST /auth/refresh
- POST /auth/sign-out
- GET  /auth/session
Plus app data:
- GET /items (Authorization required)

CORS: any localhost / 127.0.0.1 origin, or Vite proxy /api → mock.
Access TTL ≥ 15 minutes for the scaffold.

================================================================================
ROUTES / SCREENS
================================================================================
1. /sign-in — email + password; call auth.signIn; navigate to /app
2. /sign-up — email + password + displayName; call auth.register (NOT signUp); navigate to /app
3. /app — protected; session user summary
4. /app/items — query list; loading/error/empty
5. Sign-out — auth.signOut; privileged cache cleared via epoch

================================================================================
SYSTEM WIRING RECIPE
================================================================================
create-system (no DOM):
1. createLocalAuthProvider({ baseUrl }) — endpoints = defaults unless overridden
2. createAuth({ provider, storage: createSessionStorageAuthStorage("sometic-auth-app") })
3. createHttp({ baseUrl }) naked
4. createQueryClient({ defaultOptions: { queries: { retry: false, refetchOnSubscribe: false, staleTime: 60_000 } } })
5. createHeadController(); createThemeController({ themes: [lightTheme, darkTheme], defaultThemeId: "light", darkThemeId: "dark", mode: "light" })
6. createAppShell({ auth, http, query, head, theme, refetchOnReauth: false })
7. return { shell, auth: shell.auth, http: shell.http, query: shell.query, head, theme }

bootstrap (DOM allowed):
- await auth.whenReady()
- applyHead + applyThemeToElement + subscriptions
- A: providers with shell.*; B: Vue equivalents; C: app context + Elements; D1/D2: globals or ESM bindings from CDN
- Page-lifetime singleton; do not dispose on remount cleanup

Route titles: head.set("route:sign-in", { title: "Sign in" }) etc. Never setTitle.

================================================================================
CDN-SPECIFIC RULES (D1 / D2)
================================================================================
- Prefer HTML-first multi-page or a tiny hash/path router; still use the same System graph.
- D1: classic script tags (IIFE). Use the package’s documented global (check CDN docs). Order scripts by dependency.
- D2: type="module" imports from pinned esm.js URLs. Prefer import maps if many packages.
- Still run a mock API process for auth-local; document how to start it.
- Do not claim npm packages are unused while also bundling them — pick CDN delivery cleanly.
- Elements: only shipped sometic-* tags; otherwise native HTML + engine controllers.
- Unit tests may be thinner for pure CDN; e2e is still required.

================================================================================
TESTING (REQUIRED)
================================================================================
Unit (Vitest preferred for A/B/C; optional-but-encouraged for D):
- shell.http is the only auth-bound client
- register path hits /auth/register (or configured endpoints)
- isAuthenticatedStatus("refreshing") is true
- form setValue then submit reaches onValid

E2E (Playwright preferred for all paths):
- register → /app
- sign-in → /app/items loads
- sign-out clears privileged UI
- remount does not throw disposed controller errors (A/B/C)

Scripts: test, test:e2e (document web + mock startup).
