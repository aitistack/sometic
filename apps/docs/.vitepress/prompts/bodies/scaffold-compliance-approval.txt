================================================================================
PRODUCT TO BUILD
================================================================================
Name: Mandate Review
Users: reviewers deciding approve/reject on policy cases; auditors reading activity.
Outcome: Case queue + right-hand review drawer + approval steps + permission-gated actions + activity audit + notification fan-out + confirm dialogs for irrevocable decisions.

================================================================================
NON-NEGOTIABLE RULES
================================================================================
- Approval engine models steps/state; server enforces dual-control / four-eyes if required
- Activity = audit trail surface (not toast history)
- Permission matrix + can() are UX; API rejects unauthorized decides
- Review UI: Drawer from the right for case detail; Dialog for final approve/reject
- createAppShell; dispose; no import-time globals
- Conservative high-contrast consumer CSS; unmistakable approve/reject
- No Invoice Desk, playgrounds, telemetry; no invented compliance-export package (build export from your API if needed)

================================================================================
REQUIRED PACKAGES
================================================================================
@sometic/approval, @sometic/activity, @sometic/notifications, @sometic/auth,
@sometic/query, @sometic/http, @sometic/app-shell,
framework /overlay (Dialog, Drawer), /data (PermissionMatrix), /button

================================================================================
DOMAIN STUBS
================================================================================
Case: { id, title, summary, state: "pending"|"approved"|"rejected", step, version }
Decision: { caseId, outcome: "approve"|"reject", comment }
ActivityEvent: { id, caseId, actorId, message, createdAt }

Permissions: cases:read, cases:decide, roles:edit

API:
- GET /cases
- GET /cases/:id
- POST /cases/:id/decide (authz + optional dual control rules)
- GET /cases/:id/activity
- notifications on assignment

================================================================================
SCREENS
================================================================================
1. Sign-in
2. Case queue (filter by state)
3. Opening a case opens right Drawer with summary + current step + activity
4. Decide → Dialog confirm → mutation → activity entry → notify watchers
5. Roles page with Permission matrix for reviewer roles

================================================================================
WIRING RECIPE
================================================================================
1. App Shell auth/http/query
2. Query keys ["cases"], ["cases", id], ["cases", id, "activity"]
3. approval controller drives step UI; final decide hits API
4. On success: invalidate + activity refresh + notification fan-out (mock OK)
5. Hide decide button without cases:decide; still verify 403 if forced
6. Drawer focus trap / Esc close; restore focus to queue row

================================================================================
IMPLEMENTATION STEPS
================================================================================
1. Vite + mock API with authz rules
2. System bootstrap
3. Queue + drawer
4. Approval step UI + decision dialog
5. Activity panel
6. Notifications
7. Permission matrix page
8. Conservative CSS + README (legal SoR, Drawer CE gap, export-out-of-scope)

================================================================================
ACCEPTANCE CRITERIA
================================================================================
[ ] Decide without permission fails in API and is blocked in UI
[ ] Confirm dialog required before approve/reject
[ ] Activity records the decision actor and outcome
[ ] Drawer does not scroll the underlying page (portal/fixed UI)
[ ] No claim that Sometic stores regulatory proof beyond your API
[ ] dispose safe
