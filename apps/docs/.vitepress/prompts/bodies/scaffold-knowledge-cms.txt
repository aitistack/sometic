================================================================================
PRODUCT TO BUILD
================================================================================
Name: Quill Knowledge Base
Users: editors drafting articles; readers viewing published pages.
Outcome: Article list + editor with draft autosave + undo/redo + conflict handling on save races + SEO head on published routes.

================================================================================
NON-NEGOTIABLE RULES
================================================================================
- Forms bind article fields; rich text is your component feeding form state
- @sometic/drafts for autosave (omit secrets); debounce writes
- @sometic/history for intentional undo/redo command stack
- @sometic/conflict for concurrent save policy (reload vs merge prompt) — not a full CRDT suite
- Published routes set @sometic/head; drafts should be noindex if publicly reachable
- Long-term revision history beyond undo stack = your API if needed
- createAppShell for editor session; dispose; no import-time globals
- No Invoice Desk, playgrounds, telemetry, invented rich-text package

================================================================================
REQUIRED PACKAGES
================================================================================
@sometic/app-shell, @sometic/auth, @sometic/http, @sometic/query,
@sometic/forms, @sometic/drafts, @sometic/history, @sometic/conflict, @sometic/head,
plus RICH_TEXT_LIB of your choice

================================================================================
REPO LAYOUT

  styles/cms.css
README.md                     // name rich text library

================================================================================
DOMAIN STUBS
================================================================================
Article: { id, slug, title, content, status: "draft"|"published", version, updatedAt }

API:
- GET /articles
- GET /articles/:id
- PUT /articles/:id (If-Match version; 409 on conflict)
- POST /articles/:id/publish
- GET /p/:slug (published)

================================================================================
SCREENS
================================================================================
1. Sign-in
2. Article list (query)
3. Editor: title + rich text + autosave indicator + undo/redo buttons
4. Conflict modal on 409
5. Published reader page with head/seo

================================================================================
WIRING RECIPE
================================================================================
1. App Shell
2. Load article into forms; mirror draft via drafts engine
3. Wrap edits in history commands
4. Save sends version; on 409 open conflict UI (reload server copy or overwrite with confirm)
5. Publish mutation updates status + head fields on public route
6. Debounced draft persistence separate from server save

================================================================================
IMPLEMENTATION STEPS
================================================================================
1. Vite + mock with version conflicts
2. System + list/detail queries
3. Editor form binding + chosen rich text lib
4. Drafts autosave
5. History undo/redo
6. Conflict modal
7. Published page + head
8. README honesty (no CE for primitives; no rich-text package)

================================================================================
ACCEPTANCE CRITERIA
================================================================================
[ ] Autosave restores after reload of editor route
[ ] Undo/redo changes content via history
[ ] Forced mid-air conflict (two tabs) surfaces conflict UI
[ ] Published page title tag matches article title
[ ] package.json includes explicit rich text dependency (or documents textarea-only)
