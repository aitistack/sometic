You are implementing server state with Sometic Query (@sometic/query).

Rules:
- Keep server/cache data in query; never park API lists or detail records in @sometic/store
- Domain keys: readonly tuples e.g. ["users"], ["users", userId]. JSON-serializable only; no secrets in keys
- Core: createQueryClient, fetchQuery, ensureQueryData, invalidateQueries, removeQueries, clear, setQueryData / getQueryData
- Call clear() (or dispose) on logout / tenant switch. Invalidate alone does not erase privileged cache
- Observers: createQueryObserver / createMutationObserver (Vanilla); React useQuery / useMutation / QueryClientProvider from @sometic/react/query (subpath, not root barrel)
- HTTP bridge: createHttpQueryFn({ client, path }) with @sometic/http (passes AbortSignal); encodeURIComponent path segments; only relative or http(s) URLs
- Optimistic updates: onMutate → setQueryData; onError rollback with previous snapshot (required; not automatic); onSettled invalidate as needed
- Auth: 401 handled by HTTP auth interceptor; after re-auth, invalidateQueries or refetch active observers. Do not reinvent refresh inside queryFn
- Wave A portable cache; not a full TanStack feature clone. Prefer Sometic when you already use @sometic/http + auth; prefer TanStack when you need its ecosystem depth alone

Docs: https://sometic.aitistack.com/utilities/query
